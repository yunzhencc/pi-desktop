# Pi Desktop 设计系统总纲

用于约束后续 UI 设计、实现和评审，面向 Electron 桌面生产力工具的界面系统说明。

## 目标

- 建立一套克制、清晰、高密度的桌面工作台视觉体系。
- 避免为单个页面或组件另起视觉体系。
- 在浅色和深色模式下保持可读性、层级和交互反馈一致。

## 核心色值

| 语义 | 浅色 | 深色 |
| --- | --- | --- |
| 编辑器背景 | `#ffffff` | `#111111` |
| 编辑器前景 | `#0d0d0d` | `#fcfcfc` |
| 侧栏背景 | `#fcfcfc` | `#131313` |
| 侧栏前景 | `#212121` | `#8f8f8f` |
| 焦点 / 链接 / 按钮 | `#0169cc` | `#0169cc` |
| 新增状态 | `#00a240` | `#00a240` |
| 删除 / 错误状态 | `#e02e2a` | `#e02e2a` |

## 设计基调

- 克制，不使用强装饰背景、渐变球、bento 装饰或营销页式 hero。
- 高可读，文本、代码、日志、会话内容优先。
- 高效率，常用操作可快速定位，界面状态清楚。
- 低干扰，辅助按钮、边框和提示应弱化但可发现。
- 桌面优先，侧栏、工具栏、输入区和滚动内容必须稳定。

## 颜色系统

颜色应围绕语义 token 建立，不直接散落硬编码色值。

推荐语义层级：

- `background`：主页面背景。
- `foreground`：主文本。
- `muted`：弱背景。
- `muted-foreground`：次级文本。
- `border`：默认边框。
- `input`：输入控件边框或背景。
- `ring`：focus ring。
- `primary`：主操作、选中状态、链接。
- `secondary`：次级操作背景。
- `destructive`：删除、危险、失败。
- `success`：成功、完成、新增。
- `warning`：警告、需确认。

建议方向：

- 浅色模式以接近白色的内容背景和极浅侧栏背景为主。
- 深色模式以接近黑色但非纯黑的背景建立层级。
- 主品牌色可参考 Codex 的蓝色方向，用于焦点、链接、主按钮和选中态。
- 不要让品牌色大面积铺满侧栏、页面背景或会话容器。
- 错误、成功、警告色应保持稳定，不随页面局部风格变化。

## 字体和排版

- 正文优先使用系统 sans-serif，保证桌面端渲染稳定。
- 代码、路径、命令、日志和快捷键使用等宽字体。
- 字号层级保持少量固定等级，不为单个组件临时定义新等级。
- 工作台内容避免超大标题；大字号只用于空状态或明确的页面级标题。
- 会话内容需要舒适行高，工具栏和列表项需要更紧凑行高。
- 中英文混排要避免负 letter-spacing。

建议层级：

| 用途 | 建议 |
| --- | --- |
| 页面标题 | 18-24px / semibold |
| 分区标题 | 14-16px / medium 或 semibold |
| 正文 | 13-15px / regular |
| 次级说明 | 12-13px / regular |
| 辅助标签 | 11-12px / medium |
| 代码 / 日志 | 12-14px / monospace |

## 间距和密度

- 使用 4px 或 8px 为基础间距阶梯。
- 侧栏、列表、工具栏保持较高密度，避免像营销页一样大留白。
- 会话正文和 composer 保留足够阅读空间。
- 组件内部间距小于组件之间间距，模块之间间距最大。
- 固定 header、footer、toolbar、composer 不能遮挡滚动内容。

推荐节奏：

| 用途 | 建议 |
| --- | --- |
| 紧凑控件内部 | 4-8px |
| 普通控件内部 | 8-12px |
| 列表项垂直间距 | 6-10px |
| 分区间距 | 16-24px |
| 页面边距 | 16-32px |

## 圆角、边框和阴影

- 常规控件圆角建议 6-8px。
- 卡片、浮层、composer 可以略大，但不应形成圆润玩具感。
- 桌面工作台优先通过边框、背景层级和分割线表达结构。
- 阴影只用于 popover、dropdown、modal 等浮层。
- 深色模式中边框不能完全消失，需要维持可识别层级。

## 图标

- 图标优先使用 lucide 或项目已有一致图标库。
- 不使用 emoji 作为结构性图标。
- 图标按钮必须有稳定尺寸，不能因为 hover / active 状态改变布局。
- Icon-only 控件必须提供 accessible label。
- 不熟悉或低频操作图标需要 tooltip。

## 组件规则

### 按钮

- 主按钮只用于提交、创建、发送、确认等主要动作。
- 次按钮用于非破坏性辅助动作。
- 危险按钮只用于删除、清空、断开连接等不可逆或高风险操作。
- 所有按钮必须有 default、hover、pressed、focus、disabled、loading 状态。
- 一个视图内避免多个同等视觉重量的主按钮。

### 输入区

- 输入框必须有明确 focus 状态。
- 多行 composer 需要最大高度和滚动策略。
- 发送、停止、附件、工具等按钮应位置稳定。
- 错误提示应靠近输入区域，不要只用 toast。
- loading 和 disabled 状态不能造成输入区高度跳动。

### 侧栏

- 侧栏用于项目、会话、导航和状态入口。
- 当前项、hover 项、focus 项和 pinned / active 状态必须可区分。
- 列表项高度应稳定，避免标题长度导致整体跳动。
- 长项目名和会话名应截断，并保留 tooltip 或详情入口。

### 会话内容

- 用户消息、助手消息、工具输出、错误和系统提示应有清晰区分。
- 代码块需要等宽字体、可复制入口和稳定滚动。
- 工具调用结果应可扫描，不用强装饰边框压过正文。
- 长内容要避免撑破主布局。

### 浮层

- Dropdown、popover、tooltip、modal 需要明确层级。
- Modal 必须有明确关闭方式和焦点管理。
- Tooltip 只补充解释，不承载必须操作的信息。
- Popover 不应遮挡触发控件和关键上下文。

## 交互状态

所有可交互元素至少覆盖：

- default
- hover
- active / pressed
- focus-visible
- selected / current
- disabled
- loading
- error

交互状态不能只靠颜色；必要时结合边框、背景、图标或文案。

## 动效

- 常规交互动效保持 150-300ms。
- 动效用于表达状态变化、空间关系和反馈，不用于装饰。
- 展开、折叠、浮层出现、列表插入和 loading 应保持一致节奏。
- 重复或大幅动效必须支持 `prefers-reduced-motion`。
- 动效不能导致文本、按钮或布局错位。

## 响应式和桌面适配

- 至少覆盖 375px、768px、1024px、1440px。
- 桌面窗口缩小时，侧栏、主内容和 composer 应有明确压缩策略。
- 固定格式 UI 需要 min-width、max-width、overflow 或换行规则。
- 长文本、路径、代码、URL 必须有截断或滚动策略。
- 不使用移动端 safe area、haptics、bottom nav 等规则来指导桌面 Web / Electron 设计。

## 可访问性

- 主文本对比度至少 4.5:1。
- 次级文本对比度至少 3:1。
- focus 顺序应匹配视觉顺序。
- hover-only 操作也必须能通过键盘访问。
- 状态变化使用语义属性，例如 `aria-current`、`aria-expanded`、`aria-pressed`、`aria-busy`、`role=status`、`aria-live`。
- 颜色不能作为唯一状态提示。

## 交付检查

- [ ] 浅色和深色模式均已检查。
- [ ] hover、focus、pressed、disabled、loading、empty、error 状态完整。
- [ ] 固定 header、toolbar、sidebar、composer 不遮挡滚动内容。
- [ ] 长文本不会溢出容器。
- [ ] 动效符合 `prefers-reduced-motion`。
- [ ] 图标来自一致体系，icon-only 控件有可访问名称。
- [ ] 没有为单个页面引入独立视觉体系。
- [ ] 没有使用装饰性渐变、巨大卡片或营销页式 hero 掩盖信息结构。

## 页面级覆盖

页面级规则只记录局部差异，不重复本文件的主规则。

建议路径：

- `design-system/pages/conversation.md`
- `design-system/pages/settings.md`
- `design-system/pages/workspace.md`

格式：

```md
# <页面名> 覆盖规则

## 继承

默认继承 `design-system/MASTER.md`。

## 覆盖

- <具体规则>：<原因>
```

## 反模式

- 把桌面工作台做成营销页。
- 为单个组件新增独立颜色、圆角、阴影或动效体系。
- 使用 emoji 代替正式图标。
- 只做默认状态，不做交互和错误状态。
- 只验证浅色模式，不验证深色模式。
- 让动态文本、loading 或 hover 状态改变固定控件尺寸。
- 用移动 App 规则替代 Electron 桌面端规则。
